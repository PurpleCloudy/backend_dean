# Матрица сценариев React-фронтенда и API

Источник: Lyaako/dean-agent-front, ветка `react-frontend`, SHA `e7d5f872ff072372d12d1890b7b90a8dd281bfc0`. Инвентаризация 10.10.2026 по прямому чтению всех `frontend/src` модулей и конфигурации. `mockup/` — макеты, не маршруты приложения. Все API ниже имеют префикс `/api/v1`.

Это разумная матрица классов ситуаций, а не декартово произведение полей. Строка — проверяемый сценарий; наличие строки не означает успешного выполнения. Фактические результаты HTTP/браузера фиксируются отдельно в итоговом протоколе проверки. Статус «нет UI» означает отсутствие функции на этой ветке, а не дефект API.

## Вход, права и навигация

| ID | Действие | API / состояние | Положительная проверка | Отрицательная / граничная проверка |
|---|---|---|---|---|
| A01 | Вход | POST `/auth/login`, GET `/auth/me` | Валидный пользователь видит свои разделы | Пустые поля не отправляются; неверный пароль, ограничение попыток и недоступность показаны без утечки |
| A02 | Перезагрузка / истечение access | POST `/auth/refresh`, CSRF + cookie | Перезагрузка сохраняет вход, API повторяет запрос после refresh | Истёкшая/отозванная cookie выводит на вход; неверный CSRF отклонён |
| A03 | Две вкладки | Web Locks + refresh | Общая cookie обновляется последовательно | Одновременное обновление не отзывает рабочую сессию |
| A04 | Выход / смена пользователя | POST `/auth/logout` | Очищаются token/query cache, следующий пользователь не видит прежних данных | Старый access и удалённая сессия запрещены; поздний ответ старого чата не попадает новому пользователю |
| A05 | Меню и прямые URL | GET `/schema` | 7 доступных разделов, профиль, роль; неизвестный URL возвращает `/students` | Student/teacher не получают чужие строки или действия через прямой URL/API; сбой schema показан |
| A06 | OLAP | `/olap`, без API | Честная заглушка «Скоро» | Нет утверждения о работающей аналитике |

## Фактические ограничения действий по текущей схеме API

Права ниже описывают кнопки и серверные операции, а видимые строки дополнительно ограничены институтом/владельцем. «Сотрудники» здесь — роли admin/director/dean_staff.

| Ресурс экрана | Создать | Изменить | Удалить |
|---|---|---|---|
| student | Только приказ зачисления, сотрудники | Сотрудники: основа/общежитие/иностранный статус; остальные изменения приказами | Нет UI |
| study_group, schedule_slot, academic_work, practice_placement | Сотрудники | Сотрудники | Сотрудники, с проверкой связей |
| document_request | Сотрудники; student — только собственная заявка с начальным статусом | Сотрудники | Нет UI/API-операции |
| employee | Только admin | Трудовые поля и ФИО в кадровой карточке — только admin | Только admin |

teacher/student имеют просмотр разрешённых им записей; student дополнительно создаёт свои заявки. ФИО сотрудника и его трудовые поля сохраняются отдельными запросами, поэтому частичный успех теперь сообщается явно.

## Общие таблицы и формы

Применимость: `/students`, `/groups`, `/schedule`, `/works`, `/requests`, `/practice`, `/employees`. Проверка каждой загрузки обязательна; общий механизм поиска/форм проверяется на представительных типах, не 7 раз для одинакового поведения.

| ID | Действие | API / состояние | Положительная проверка | Отрицательная / граничная проверка |
|---|---|---|---|---|
| T01 | Загрузка семи разделов | GET `/resources/{view}` | Данные каждого view, подписи и ключи согласованы; сотрудник нескольких институтов отображается одной строкой со всеми доступными подразделениями | Пустая выдача, 403, 5xx/сеть, «Повторить» |
| T02 | Поиск | Локально по текстовым колонкам | ФИО/номер/тема, регистр, ё/е; очистка | Нет совпадений; поиск не обещает искать скрытые/нетекстовые поля |
| T03 | Фильтры | enum/bool/num/date | Несколько значений, числовой и датовый диапазон, снятие одного, сброс всех | null; обратные границы; пустой список значений |
| T04 | Сортировка | Локально, ASC/DESC/исходный | Текст, число из decimal-строки, день недели | null; одинаковые значения |
| T05 | Страницы | API по 500, UI по 20 | Переход вперёд/назад; последний лист; фильтр возвращает страницу 1 | >500 строк; лимит 20000 не должен молча представлять неполные данные как все |
| T06 | Форма существующей записи | GET `/schema`, GET `/resources/{table}?pk=` | Правильная строка; только разрешённые поля | Удалённая строка; отказ чтения; ошибка lookup не превращается в пустое успешное значение |
| T07 | Справочники формы | GET `/resources/{lookup}` | Поиск подписи; выбор мышью/Enter; Escape; nullable очистка | Нет вариантов; текущий вариант сохраняется при фильтре; серверная ошибка |
| T08 | Сохранение / закрытие | POST/PATCH `/resources/{table}` | Добавление и обновление видны после перечитывания | Required, число/границы/даты, duplicate/FK/domain conflict; ошибка оставляет форму; отмена не пишет |
| T09 | Несохранённое / удаление | Dialog, DELETE `/resources/{table}?pk=` | Сохранить / не сохранять / продолжить; подтверждённое удаление | Отмена удаления; зависимые строки защищены; read-only не пишет |

## Границы доступного UI

Отдельных экранов оценок, посещаемости, учебных планов, справочников, организаций, пользователей/ролей, аудита, администрирования очереди и управления файлами здесь нет. Часть этих данных читается через таблицы/lookup или агент. OLAP — заглушка. Это нельзя записывать как успешно проверенный интерфейс.

LLM проверяется отдельно от HTTP-протокола. Сценарий с детерминированным peer подтверждает контракт и сохранение, но не качество SQL/reasoning/RAG реальной модели. Локальная модель без подтверждённого tool-calling или другая embedding-модель не доказывает полноту работы исходного агента.

## Как перенести исправления во фронтенд

Исправленный checkout находится в `.local/dean-agent-front`, переносимый diff — `docs/patches/frontend-react-frontend.patch` этого backend-репозитория. Backend-исправления сами по себе не переключают ранее опубликованный React-клиент на серверную историю.

В чистом checkout фронтенда на `react-frontend`, исходный SHA `e7d5f872ff072372d12d1890b7b90a8dd281bfc0`, выполните `git apply --check <путь-к-patch>`, затем `git apply <путь-к-patch>`. При новых изменениях коллеги сначала согласуйте конфликты; не перезаписывайте их. Применение проверено на отдельном чистом клоне исходного SHA; содержимое изменённых файлов совпало с рабочей версией после нормализации CRLF/LF.

Из корня frontend-репозитория: `npm --prefix frontend ci`, `npm --prefix frontend test`, `npm --prefix frontend run build`. Для Windows перед `npm ci` остановите свой Vite: он держит нативную библиотеку сборщика открытой. Затем скопируйте `frontend/.env.example` в `frontend/.env.local`, задайте `VITE_API_TARGET` и запустите `npm --prefix frontend run dev`. API по умолчанию — `http://localhost:8000`; изолированная проверка использует `http://127.0.0.1:18000`. Нужно применить backend-миграции до `head` (сейчас `0005`): история чатов появилась в `0004`, исправление повторяющихся строк сотрудников — в `0005`.

Проверки фронтенда: чистый `npm ci`, 13 модульных проверок контракта, production build и переносимый `gen:api` в Windows прошли. Тесты с явно заданными ответами не выдают себя за LLM-проверку. Сгенерированный `openapi.d.ts` — игнорируемый локальный результат, в patch не включён.

`npm audit` сообщил 3 moderate-записи одной цепочки `mammoth → argparse → sprintf-js` (DoS format precision), без high/critical. `argparse` вызывается в `mammoth/bin/mammoth`, не в импортируемом `mammoth/lib`; ссылок на argparse/sprintf в production bundle не найдено. Разрушающий downgrade mammoth до 0.3.29 не применялся. Сборщик также предупреждает о chunk >500kB; это предупреждение размера, не ошибка сборки.

Старые `deanery.chats.{user_id}` не удаляются и автоматически не загружаются на сервер. В UI показывается ограничение; серверные диалоги доступны вне браузерного хранилища. Черновики остаются временными, выбор последнего чата — локальной настройкой. Ошибка после подготовки предложения не скрывает его: карточка решения показывается и в сообщении ошибки.

# Локальный прототип

Адрес: **http://127.0.0.1:5173**. Вход обычный, по логину и паролю.
Личные данные для входа сохраняются в `.local/prototype_runtime/local-login.txt`.
Файл доступен текущему пользователю Windows; он исключён из Git. Пароли не выводятся
в журнал запуска. Для просмотра всех разделов используйте учётную запись ADMIN,
для проверки ограничений — STAFF и STUDENT из этого же файла.

В PowerShell из корня проекта:

```powershell
./scripts/prototype.ps1 -Action Start
./scripts/prototype.ps1 -Action Status
```

`Start` использует уже подготовленную локальную установку: Docker Desktop, образ
бекенда `deanery-backend:frontend-qa`, файлы окружения и Compose в
`.local/frontend_verification/`, переопределение реальных моделей
`.local/bge/compose.real.yaml`, установленный BGE и клонированный React-фронтенд
в `.local/dean-agent-front/frontend`. Это запуск подготовленного прототипа на
данном компьютере, а не установщик на чистую машину. Установка моделей описана в
[LOCAL_MODELS.md](LOCAL_MODELS.md).

Скрипт запускает только стек `deanery-frontend-qa`; существующие данные и другие
стеки не очищаются. Если BGE или модель уже работают, они переиспользуются.
Фронтенд собирается и работает в отдельном скрытом процессе Vite preview:
закрытие терминала не завершает сервер. Повторный `Start` обновляет только
опознанный собственный процесс. Если порт5173 занят чужим процессом, запуск
останавливается с объяснением и никого не завершает. Логи находятся в
`.local/prototype_runtime/`. После перезагрузки Windows откройте Docker Desktop
и повторите запуск. Автозапуск системы не устанавливается.

`Status` проверяет соответствие страницы текущей сборке, API и все его зависимости,
загруженный BGE-M3, наличие Qwen с контекстом16384 и процесс обработчика задач.
`healthy: true` означает готовность сервисов; это не гарантия правильности ответа
языковой модели. LM Studio и BGE доступны локально без собственной авторизации,
поэтому этот режим предназначен для данного компьютера. Сам API сохраняет
авторизацию, роли и ограничения доступа к записям.

## Данные и аналитика

Новые серверные каталоги файлов, задач и отложенных действий сохраняются между
входами и перезапусками. Права на каждую выдаваемую запись проверяются заново.
Каталоги файлов и задач используют `next_offset`: иногда страница пуста, но
продолжение есть, если доступ к просмотренным кандидатам был отозван. Клиент
продолжает по `next_offset`; это не число доступных пользователю записей.

ROLAP выполняется непосредственно в PostgreSQL, в области доступа пользователя:
можно менять измерения и показатели, применять несколько фильтров, раскрывать
группу до исходных записей и возвращаться к сводке. Доступны контингент,
успеваемость и посещаемость. Итоги вычисляются по всей отфильтрованной выборке,
даже когда на экране только одна страница. SQL от пользователя не принимается.

- Контингент: один студент, его текущие группа/институт/статус.
- Успеваемость: все попытки и этапы, кроме отменённых ведомостей. Средний балл
  исключает NULL. «Записи с оценкой» означает наличие баллов, а не успешную сдачу.
  Уникальные студенты и средние пересчитываются заново для итогов.
- Посещаемость: только существующие отметки занятий. Отсутствие отметки не
  доказывает отсутствие занятия. Процент — присутствия / все отметки.

Фильтры `eq/ne` с NULL означают IS NULL / IS NOT NULL; сравнение `ne` с обычным
значением, как в SQL, исключает NULL. `in` принимает1–100 значений и может включать
NULL. В запросе не более3 измерений,5 показателей и12 фильтров; на странице до200
строк. Группировки и итоги читаются в одном согласованном SQL-снимке.

## Модель и границы проверки

Используются настоящий Qwen2.5-7B-Instruct-Q4_K_M в LM Studio и BAAI/bge-m3 на CPU.
Используется точный upstream commit `d92bf5fbfc5b37c3236a6454aeffa5374fe88b11`. Изменения интеграции расположены в адаптере; включённые файлы агента сверены с upstream. Адаптер добавляет описание
реальной схемы и правил инструментов. Ограничения SQL и подтверждение человеком
не ослаблены. Предложение изменения само по себе не меняет рабочие записи.

У локальной модели наблюдались ошибки выбора таблицы и составления предложения.
Сохранённые HTTP/SSE-трассы успешных и неуспешных прогонов находятся в
`.local/prototype_runtime/real-model-results/`; результаты pytest — рядом.
Окончательная проверка действий модели опирается на результат инструмента,
предпросмотр и фактическое состояние БД, а не только её текстовый ответ.

В чате доступны TXT, CSV, DOCX и PDF с текстовым слоем: можно загрузить новый файл или выбрать конкретную готовую сохранённую версию. Допускается до 5 файлов, 10 МБ каждый и 20 МБ вместе; сообщение с файлами — до 2000 символов. Оригиналы, версии и история сохраняются. Просмотр сохранённого файла заново проверяет доступ на сервере. В разделе «Документы» откройте карточку и нажмите «Просмотреть» возле готовой версии; PNG можно просмотреть и при текстовом профиле агента.

PNG/JPEG/WebP и PDF-сканы можно хранить, но текстовый профиль Qwen их не читает. Автоматического OCR нет. Установленную визуальную модель не запускали: после временной выгрузки Qwen свободно 1.61 GiB RAM при принятом минимуме 5 GiB. Qwen восстановлена с контекстом 16384. Даже текстовая модель иногда не вызывает инструмент или ошибается в фактах; подтверждены две такие ошибки, подробно в [протоколе вложений](ATTACHMENT_VERIFICATION.md).

Текущая схема — `0006`, frontend — `index-Ckz215-3.js`, [финальная готовность](../.local/attachment_qa/results/final-manifest.json). В установке синтетические данные и учебные документы; это демонстрация, не готовое подключение к реальным персональным данным университета.

После изменения кода API образ нужно пересобрать перед запуском:

```powershell
docker compose --env-file .local/frontend_verification/runtime.env -f .local/frontend_verification/compose.yaml -f .local/bge/compose.real.yaml build api
```

Откат выполняйте совместимым со схемой 0006 образом или последующим исправлением. Не понижайте миграции истории и метаданных инструментов: это потребовало бы удаления сохранённых сведений. Старый образ сохранён как `deanery-backend:pre-attachments`, но его проверка готовности ожидает прежнюю схему, поэтому простой запуск этого образа не является готовым откатом нынешней БД. Не удаляйте тома, файлы, версии, задания или историю.

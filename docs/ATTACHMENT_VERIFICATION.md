## Исправления, которые потребовались

1. Исходный обновлённый агент помещал извлечённый текст в сохранённое пользовательское сообщение. Теперь модель получает разрешённый контекст текущего запуска, а в историю записывается исходный запрос. Следующий запуск не получает скрытый исходный текст из этой истории. Уже показанные ответы ассистента могут цитировать файл и остаются историей: отзыв доступа не стирает уже прочитанное.
2. Старый FileViewer мог использовать глобальный кеш вместо текущего авторизованного скачивания. Кеш оригиналов удалён; сохранённая версия всегда проверяется сервером. Собственный ещё не отправленный оригинал можно просмотреть локально. Кеш миниатюр очищается при смене владельца; поздние завершения и смена просматриваемого файла покрыты тестами.
3. Первый реальный UI-запрос вызвал reader, но старая CHECK для tools_used не принимала его имя. Callback получил 422, откат записи оставил ambiguous. Миграция 0006 добавляет только read_attachment_text, сохраняя три прежних имени, предел 300, права и RLS. SSE сообщает безопасную ошибку при сбое записи; done отправляется после фиксации транзакции. Старый тестовый запуск штатно завершён как failed только после остановки прежнего экземпляра агента; [аудит восстановления](../.local/attachment_integration/qa-sse-recovery-0006.json) сохранён. Ответ не записывался вручную как успешный.
4. Клиент показывал одновременно локальную ошибку обрыва потока и серверную ошибку. Сопоставление теперь выполняется по run_id, а не несинхронным часам. Реальное обновление страницы показывает одну ошибку; дополнительные гонки проверены клиентскими тестами.

5. В каталоге документов не было отдельного просмотра готовой версии. Добавлена кнопка «Просмотреть» с существующим просмотрщиком и свежей проверкой доступа. Версии в обработке недоступны для просмотра; агентская capability не блокирует обычный просмотр собственного изображения. Проверены компонентный сценарий старой готовой версии и настоящий клик PNG.

## Оставшиеся ограничения

- **Две реальные ошибки Qwen сохранены:** поздний факт в пяти документах выдуман без чтения продолжения; ответ на старую версию содержит JSON вызова как текст, без самого вызова. Повторов для подгонки результата не делали. Правильная доставка и сохранение не означают правильный ответ модели.
- **Vision NOT-RUN:** после выгрузки только Qwen свободно 1.61 GiB RAM при принятом минимуме 5 GiB; 6.76 GiB VRAM было достаточно. Gemma не загружалась, новых вызовов модели не было, чужие приложения и BGE не останавливались. Qwen восстановлена с контекстом 16k; [протокол](../.local/attachment_integration/vision-trial.json). Фото и сканы хранятся и скачиваются, но текущий профиль их не читает.
- Начальный контекст: один целый chunk на файл, до 6000 символов для пяти файлов. Reader читает один chunk по умолчанию, максимум два за вызов и пять дополнительных за запуск; context_budget_exhausted отличается от конца файла. Только при запросе с вложениями старые целые пары истории ограничены 6000 UTF-8 байт; сохранённая история не удаляется. Это консервативные лимиты, а не точный токенизатор и не гарантия беседы произвольной длины.
- Новый запрос без повторного приложения того же файла, гонка поздних ответов preview, отправка до готовности всех файлов и будущие визуальные профили покрыты частично чтением кода и тестами либо не запускались. Это не доказательство реальных кликов или ответов модели. EICAR, все десять визуальных страниц и разрушительные стресс-тесты парсеров в этот прогон не включались.

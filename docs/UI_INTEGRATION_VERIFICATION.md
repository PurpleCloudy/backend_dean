## Границы безопасной проверки CRUD

Успешный create/update/delete можно подтвердить на **собственной новой fixture без внешних ссылок**, например синтетическом organization_contact, и сравнить его точный ID/поля в DB после каждого реального UI действия. Фиксировать audit и удалить только свою новую fixture, когда нужен delete test. Ошибки и отказ в правах проверяются без обхода. Для приказов, оценок, исправлений, отпуска, отчисления, пользователей и их сеансов — открыть форму/поля/validation/cancel; успешное исполнение допускается только на явно подготовленной disposable цепочке с отдельным решением владельца QA. Не выдавать просмотр формы за successful workflow execution.
